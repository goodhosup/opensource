AI와 오픈소스는 서로를 키우는 관계입니다. AI는 오픈소스 위에서 만들어졌고, 이제 AI가 오픈소스를 만드는 방식, 지키는 방식, 정의 자체를 바꾸고 있습니다.

## 한눈에 보기
| 영역 | 긍정적 영향 | 부정적 영향·과제 |
|---|---|---|
| 개발 생산성 | AI 코딩 도구로 기여 문턱이 낮아짐 | 검증되지 않은 AI 생성 코드, 저품질 PR 증가 |
| 메인테이너 | 코드 리뷰·이슈 분류·문서화 자동화 | AI가 만든 허위 버그 리포트로 검토 부담 증가 |
| 인프라 | 공개 모델·도구로 누구나 AI를 만들 수 있음 | AI 학습용 크롤러 트래픽으로 프로젝트 서버 부담 |
| 라이선스·저작권 | 공개 가중치 확산 | 학습 데이터 출처, AI 생성 코드의 라이선스 오염 위험 |
| 보안 | AI 기반 취약점 탐지·자동 패치 | AI가 공격 자동화에 쓰임, 존재하지 않는 패키지 추천(슬롭스쿼팅) |
| 정의와 정책 | 오픈소스 AI 정의 마련 | "오픈 워싱"(이름만 오픈) 논쟁 |

## 1. 오픈소스가 AI를 만든다
- 오늘날 AI의 기반은 대부분 오픈소스입니다. PyTorch, TensorFlow, Hugging Face Transformers, Jupyter, Kubernetes 등.
- 공개 모델(Llama, Mistral, Qwen, DeepSeek, Gemma 등)이 등장하면서 대기업이 아니어도 AI를 직접 실행·미세조정할 수 있게 됐습니다.
- 2025년 초 DeepSeek-R1이 MIT 라이선스로 공개되며 "오픈 모델도 최상위 성능에 근접할 수 있다"는 인식이 확산됐습니다.
- 국가 차원에서는 특정 해외 기업에 의존하지 않는 **소버린 AI** 전략의 핵심 수단으로 오픈소스가 쓰입니다. 국내의 2026 오픈소스 AI·SW 지원사업(92억 원)도 같은 흐름입니다.

## 2. AI가 오픈소스 개발 방식을 바꾼다
- **기여 확대**: AI 코딩 도구 덕분에 초보자도 코드, 테스트, 번역, 문서 기여를 쉽게 시작할 수 있습니다.
- **메인테이너 도구**: 이슈 분류, PR 요약, 리뷰 보조, 릴리스 노트 작성에 AI 활용이 늘고 있습니다.
- **부작용**: AI로 대량 생성된 저품질 PR과 허위 보안 리포트("AI 슬롭")가 늘었습니다. curl 프로젝트는 2025년부터 AI가 만든 근거 없는 리포트에 공개적으로 문제를 제기했고, 결국 **2026년 2월 1일부로 HackerOne 버그 바운티(포상금) 프로그램을 종료**했습니다. 저품질 리포트를 보낼 유인을 없애고 소수 메인테이너를 보호하기 위해서입니다. 일부 프로젝트는 AI 사용 고지 정책을 도입했습니다.
- **크롤러 부담**: AI 학습용 크롤러가 오픈소스 프로젝트의 Git 서버·문서 사이트에 과도한 트래픽을 일으켜, 차단 도구(예: Anubis)를 도입하는 사례가 생겼습니다.

## 3. "오픈소스 AI"란 무엇인가
- 소프트웨어와 달리 AI는 **코드 + 가중치 + 학습 데이터**로 이루어져, 무엇을 공개해야 "오픈"인지 기준이 필요해졌습니다.
- OSI는 2024년 10월 **오픈소스 AI 정의(OSAID) 1.0**을 발표했습니다. 코드와 가중치를 자유 조건으로 공개하고, 학습 데이터는 원본 공개 대신 "같은 시스템을 재현할 수 있을 만큼 충분한 정보"를 요구합니다.
- 공개 수준에 따른 구분

| 구분 | 공개 범위 | 예 |
|---|---|---|
| 완전 공개 | 코드, 가중치, 데이터, 학습 과정 | OLMo(AI2), Pythia |
| 오픈 웨이트(허용 라이선스) | 코드, 가중치 (Apache/MIT) | Mistral 일부, Qwen 일부, DeepSeek |
| 제한적 오픈 웨이트 | 가중치는 공개하나 사용 제한 | Llama(대규모 사용자·용도 제한), Gemma |
| 폐쇄형 | API만 제공 | 대부분의 상용 최상위 모델 |

- 사용 제한이 있는 모델을 "오픈소스"라고 부르는 것을 **오픈 워싱**이라 비판하기도 합니다.

## 4. 라이선스와 저작권 쟁점
- **학습 데이터**: 오픈소스 코드를 AI 학습에 쓰는 것이 라이선스(특히 GPL의 고지·공개 의무)를 지키는 것인지 논쟁이 있고, GitHub Copilot 관련 소송도 제기됐습니다.
- **AI 생성 코드**: AI가 학습한 코드를 거의 그대로 재현하면 원 라이선스 의무가 따라올 수 있습니다. 기업은 생성 코드에도 라이선스 검사를 적용하는 추세입니다.
- **저작권 귀속**: 사람이 아닌 AI가 만든 결과물의 저작권 인정 여부는 국가마다 정리 중입니다.
- **새로운 라이선스**: RAIL(책임 있는 AI 라이선스)처럼 용도 제한을 둔 모델 라이선스가 생겼지만, 용도 제한은 OSD와 충돌하므로 오픈소스로 보지 않습니다.

## 5. 보안 영향
- **방어**: AI로 취약점을 찾고 패치를 제안하는 도구가 늘어, 오픈소스 보안 점검 속도가 빨라지고 있습니다.
- **공격**: AI로 자동화된 공격, 악성 패키지 대량 생성이 늘고 있습니다. AI가 존재하지 않는 패키지 이름을 추천하면 공격자가 그 이름으로 악성 패키지를 등록하는 **슬롭스쿼팅**도 새로운 위협입니다.
- **AI 모델 공급망**: 모델 파일 자체에 악성 코드를 숨기는 사례가 있어, 모델에도 SBOM처럼 구성 명세(AI BOM)를 요구하는 흐름이 생기고 있습니다.
- 국내 SW 공급망 보안 강화 로드맵(2026.6)도 AI 기반 위협 탐지 체계를 포함합니다.

## 6. 정책과 규제
- **EU AI Act**: 오픈소스로 공개한 AI 모델에 일부 의무를 면제하되, 시스템적 위험이 있는 대형 범용 모델은 면제하지 않습니다.
- **한국**: 2025년 오픈소스 개발자 대회를 생성형 AI 중심으로 개편하고 "글로벌 AI 오픈소스 리더십 확보"를 내세웠으며, 2026년에는 AI 오픈소스 개발과 제조·의료·공공 분야 활용을 지원합니다. AI 기본법(2026년 1월 22일 시행)과 오픈소스 정책의 연계도 과제입니다.

## 정리
- AI 시대의 경쟁력은 상당 부분 **오픈 모델과 오픈소스 도구**에서 나옵니다.
- 동시에 **메인테이너 부담, 저작권·라이선스, 보안, "오픈"의 정의**라는 새 과제가 생겼습니다.
- 개인과 조직이 할 일: AI 생성 코드도 라이선스·보안 검사 대상에 포함하기, 모델 라이선스 확인하기, 사용하는 오픈소스에 기여·후원하기.
