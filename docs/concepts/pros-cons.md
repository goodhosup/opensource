# 오픈소스의 장점과 한계

## 장점
- **비용 절감**: 라이선스 비용 없이 시작 가능
- **품질과 보안 검증**: "보는 눈이 많으면 모든 버그는 얕다"(리누스의 법칙)
- **빠른 혁신**: 전 세계의 아이디어와 기여가 모임
- **벤더 독립성**: 공급사가 사라져도 코드는 남음
- **커스터마이징**: 필요에 맞게 직접 수정 가능
- **학습과 인재**: 코드를 보며 배우고, 기여 이력이 경력이 됨
- **표준화**: 사실상 표준(de facto standard)이 되어 생태계 형성

## 한계와 위험
- **지속가능성**: 소수 메인테이너의 무급 노동에 의존 (번아웃, 프로젝트 방치)
- **보안 공급망 위험**: 의존성 취약점(Log4Shell), 악성 패키지, 메인테이너 계정 탈취(xz 백도어 사건)
- **라이선스 위반 위험**: 카피레프트 조건을 모르고 쓰면 소스 공개 의무 발생
- **지원 책임 부재**: 보증이 없고 문제 해결은 커뮤니티나 자체 역량에 의존
- **무임승차**: 대기업·클라우드가 이용만 하고 기여는 적다는 비판 → 라이선스 변경 논쟁
- **파편화**: 포크로 인한 생태계 분열 가능

## 정리
오픈소스는 "무료 소프트웨어"가 아니라 **권리를 공유하는 개발·배포 방식**입니다. 장점을 누리려면 라이선스 준수, 보안 관리, 커뮤니티 기여라는 책임이 함께 따릅니다.
