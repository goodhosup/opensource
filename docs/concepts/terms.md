# 주요 용어 정리

## 라이선스 관련
| 용어 | 설명 |
|---|---|
| 라이선스 | 저작권자가 사용·수정·배포를 허락하는 조건 |
| 허용형(Permissive) | 조건이 느슨함. 저작권 고지만 유지하면 독점 SW에 포함 가능 (MIT, BSD, Apache 2.0) |
| 카피레프트(Copyleft) | 파생물도 같은 라이선스로 공개해야 함 (GPL, AGPL) |
| 약한 카피레프트 | 해당 파일·라이브러리 수정분만 공개 의무 (LGPL, MPL) |
| 퍼블릭 도메인 | 저작권을 포기하거나 만료된 상태 (CC0, Unlicense) |
| 듀얼 라이선스 | 오픈소스 라이선스와 상용 라이선스를 동시에 제공 |
| 소스 어베일러블(Source-available) | 코드는 공개하지만 OSD를 충족하지 않음 (BSL, SSPL 등) |
| 라이선스 호환성 | 서로 다른 라이선스의 코드를 함께 배포할 수 있는지 여부 |

## 개발·협업 관련
| 용어 | 설명 |
|---|---|
| 저장소(Repository) | 코드와 이력을 담은 공간 (GitHub, GitLab 등) |
| 포크(Fork) | 저장소를 복제해 독자적으로 개발. 프로젝트 분기의 의미로도 쓰임 |
| 풀 리퀘스트(PR) / 머지 리퀘스트(MR) | 변경 사항을 원 프로젝트에 반영해 달라는 요청 |
| 이슈(Issue) | 버그 보고, 기능 제안 등의 논의 단위 |
| 메인테이너(Maintainer) | 프로젝트를 관리하고 기여를 검토·병합하는 사람 |
| 컨트리뷰터(Contributor) | 코드, 문서, 번역 등으로 기여하는 사람 |
| 업스트림 / 다운스트림 | 원 프로젝트 / 이를 가져다 쓰는 파생 프로젝트 |
| CLA / DCO | 기여자 라이선스 동의서 / 기여 출처 인증 |
| 거버넌스 | 의사결정 구조 (BDFL, 메리토크라시, 재단, 위원회 등) |
| BDFL | 자비로운 종신 독재자. 창시자가 최종 결정권을 갖는 모델 |

## 비즈니스·운영 관련
| 용어 | 설명 |
|---|---|
| 오픈 코어(Open Core) | 핵심은 오픈소스, 고급 기능은 유료 |
| 지원·구독 모델 | 소프트웨어는 무료, 기술 지원·인증으로 수익 (레드햇) |
| SaaS / 매니지드 서비스 | 오픈소스를 호스팅 서비스로 제공 |
| OSPO | 기업의 오픈소스 프로그램 오피스. 사용·기여·컴플라이언스 관리 |
| SBOM | 소프트웨어 구성 요소 명세서. 포함된 오픈소스 목록 |
| 컴플라이언스 | 사용 중인 오픈소스의 라이선스 의무 준수 |
