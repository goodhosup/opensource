# 오픈소스의 정의와 원칙

## 한 줄 정의
오픈소스(Open Source)는 **소스 코드를 공개하고, 누구나 이를 보고·수정하고·재배포할 수 있도록 허용하는 라이선스로 배포되는 소프트웨어**와 그 개발 방식을 말합니다.

"코드가 공개되어 있다"는 것만으로는 오픈소스가 아닙니다. **사용·수정·재배포의 권리가 라이선스로 보장되어야** 오픈소스입니다. (예: 코드는 볼 수 있지만 상업적 이용을 금지하면 오픈소스가 아님)

## 오픈소스 정의(OSD, Open Source Definition)
OSI(Open Source Initiative)가 정한 10가지 기준입니다. 이 기준을 충족하는 라이선스만 "OSI 승인 오픈소스 라이선스"가 됩니다.

| # | 기준 | 의미 |
|---|---|---|
| 1 | 자유로운 재배포 | 판매·배포를 막거나 로열티를 요구할 수 없음 |
| 2 | 소스 코드 공개 | 소스 코드를 함께 제공하거나 쉽게 얻을 수 있어야 함 |
| 3 | 파생 저작물 허용 | 수정하고 같은 조건으로 배포할 수 있어야 함 |
| 4 | 원저작자 코드의 무결성 | 수정본에 다른 이름/버전을 쓰도록 요구하는 것은 허용 |
| 5 | 개인·집단 차별 금지 | 누구에게나 동일하게 적용 |
| 6 | 사용 분야 차별 금지 | 상업용, 연구용 등 용도 제한 불가 |
| 7 | 라이선스의 배포 | 재배포받은 사람도 별도 계약 없이 같은 권리 |
| 8 | 특정 제품에 종속 금지 | 특정 배포판에 포함될 때만 유효하면 안 됨 |
| 9 | 다른 소프트웨어 제한 금지 | 함께 배포되는 다른 SW에 조건을 강요하지 않음 |
| 10 | 기술 중립성 | 특정 기술·인터페이스를 전제로 하지 않음 |

## 핵심 가치
- **투명성**: 누구나 코드를 검토할 수 있어 신뢰와 보안 검증이 쉬움
- **협업**: 전 세계 개발자가 이슈, 풀 리퀘스트로 함께 개선
- **재사용**: 바퀴를 다시 발명하지 않고 기존 성과 위에 쌓아 올림
- **자율성**: 특정 벤더에 종속되지 않음(벤더 락인 회피)
- **커뮤니티 중심**: 기여와 평판을 기반으로 의사결정

## 흔한 오해
- **오픈소스 = 무료?** 대부분 무료로 얻을 수 있지만, 판매도 허용됩니다. 핵심은 가격이 아니라 권리입니다.
- **오픈소스 = 저작권 없음?** 아닙니다. 저작권은 그대로 있고, 저작권자가 라이선스로 권리를 허락하는 구조입니다. 저작권을 포기한 것은 퍼블릭 도메인입니다.
- **오픈소스 = 아무렇게나 써도 됨?** 라이선스 조건(저작권 고지, 소스 공개 의무 등)을 지켜야 합니다.
