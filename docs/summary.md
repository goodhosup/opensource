# 한눈에 보기

## 1부. 오픈소스의 개념 → [바로 가기](concepts/index.md)
- 오픈소스는 **소스 코드 공개 + 사용·수정·재배포 권리를 라이선스로 보장**하는 소프트웨어와 개발 방식이다. 핵심은 가격이 아니라 권리다.
- 기준은 OSI의 **오픈소스 정의(OSD) 10개 항목**이다. 용도·사람 차별 금지, 파생물 허용 등.
- 1983년 GNU·자유 소프트웨어 운동(윤리)에서 시작해 1998년 "오픈소스"(실용·비즈니스)로 확산됐고, 지금은 클라우드·모바일·AI의 기반이다.
- 장점은 비용, 투명성, 혁신 속도, 벤더 독립. 한계는 메인테이너 지속가능성, 공급망 보안, 라이선스 준수 부담.

## 2부. 라이선스 → [바로 가기](license/index.md)
- **허용형**(MIT, Apache 2.0): 고지만 지키면 자유롭게 사용.
- **카피레프트**(GPL, AGPL): 파생물도 같은 조건으로 공개. AGPL은 SaaS에도 적용.
- **약한 카피레프트**(LGPL, MPL): 수정한 부분만 공개.
- SSPL·BSL 같은 **소스 어베일러블**은 오픈소스가 아니며, Terraform→OpenTofu, Redis→Valkey처럼 커뮤니티 포크를 불러왔다.

## 3부. Git 사용법 → [바로 가기](git/index.md)
- Git은 분산 버전 관리 도구다. 파일은 **작업 디렉터리 → 스테이징(`add`) → 저장소(`commit`) → 원격(`push`)** 으로 흐른다.
- 작업은 브랜치(`git switch -c`)에서 하고 병합(`merge`)하거나 재배치(`rebase`)한다.
- 실수는 상황에 맞게 되돌린다: 로컬은 `restore`·`reset`, 공유된 커밋은 `revert`, 최후 수단은 `reflog`.

## 4부. GitHub 운용 방법 → [바로 가기](github/index.md)
- 기여의 표준 흐름: **포크 → 브랜치 → 커밋 → push → PR → 리뷰 → 병합**.
- 내 프로젝트에는 README, LICENSE, CONTRIBUTING, 행동 강령, SECURITY.md, 이슈·PR 템플릿을 갖추고, 브랜치 보호로 `main` 을 지킨다.
- Actions로 테스트·배포를 자동화하고, Pages로 문서를 발행하며, Dependabot·Secret scanning·CodeQL로 보안을 챙긴다.

## 5부. 생태계와 커뮤니티 → [바로 가기](ecosystem/index.md)
- 재단(ASF, 리눅스 재단, CNCF, OpenSSF)이 중립적 거버넌스를 제공한다.
- 수익 모델은 구독·지원(Red Hat), 오픈 코어(GitLab), 매니지드 서비스(MongoDB Atlas), 플랫폼 전략(Google, Meta).
- 국내: 오픈소스 개발자대회(2026 총상금 6,700만 원), 컨트리뷰션 아카데미, 오픈소스 테크데이(2026.10.7, 7회째), 오픈소스 서밋 코리아, 파이콘 한국, 커뮤니티 15곳 지원.

## 6부. 향후 방향 → [바로 가기](future/index.md)
- **보안**: SBOM 요구 확산(미국, EU CRA, 국내 SW 공급망 보안 로드맵 2026.6).
- **지속가능성**: 공공 자금, 기업 기여 확대, OSPO.
- **정책**: 국내는 AI 중심 지원으로 이동(2026 오픈소스 AI·SW 지원사업 92억 원).
- **AI**: 오픈소스는 AI의 기반이자 소버린 AI의 핵심. 반면 AI 생성 저품질 기여·크롤러가 메인테이너 부담을 키우고(curl은 2026년 2월 버그 바운티 종료), "오픈소스 AI"의 정의와 학습 데이터·생성 코드의 라이선스가 새 쟁점이다.
